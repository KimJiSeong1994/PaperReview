# RLCD 집현전 발행 전 톤앤매너 감사

## 판정

RLCD 초안은 **근거 추적, 수치 대조, 논문 진술과 해설자 판단의 분리**에서 최근 집현전 딥리뷰의 상위 수준에 이미 도달했다. 특히 7B와 30B 결과를 분리하고, 길이 교란을 단정하지 않으며, 본문·표·부록의 불일치를 원문 위치와 함께 제시한 점은 집현전의 핵심 편집 태도와 맞는다.

발행 전에는 다음 네 항목이 반드시 고쳐져야 한다.

1. `category: LLM Alignment`를 블로그 스키마의 `paper-review`로 매핑하고, 썸네일·본문 그림 경로를 `/api/blog/figures/...` 형식으로 준비한다.
2. 51,971자의 상세글과 별도로 약 5,000~7,000자의 **쉽게 읽는 글**을 만든다. 현재 초안은 `deep_content`에 해당하며 `content`로 쓰기에는 너무 길고 밀도가 높다.
3. Figure 1·2의 캡션을 줄이고, 긴 화면 묘사는 본문이나 alt text로 옮긴다. 캡션에는 출처·판본·복제 방식·해석상 주의만 남긴다.
4. References 32개를 본문에서 실제로 논증에 사용한 문헌으로 줄이고 APA형으로 통일한다. 현재 목록은 논문의 참고문헌을 거의 옮긴 형태라 집현전 발행본의 인용 목록보다 넓다.

이 네 항목을 반영하면 발행 가능한 수준이다. 비판의 방향을 약하게 만들 필요는 없지만, 몇몇 문장은 판결문처럼 들리므로 **관찰 → 근거 → 해석 한계**의 순서로 다시 배치하는 편이 좋다.

## 집현전 하우스 스타일

### 1. 도입과 메타데이터

상세글은 대체로 다음 순서를 쓴다.

1. 논문 제목·저자·연도·판본·PDF/프로젝트/코드
2. 한 문단짜리 한국어 Abstract
3. Executive Summary
4. 필요하면 목차

쉽게 읽는 글은 논문 메타데이터 뒤에 일상적 문제나 짧은 사고실험을 놓는다. 예를 들면 다음과 같다.

- `evo-ontology`: “회사 데이터에 대해 질문에 답하는 AI 에이전트를 생각해 보자.”
- `rlt`: “방금 쓴 중간 메모를 다음 줄에도 들고 가는 모습에 가깝다.”
- `ttpo`: “풀이는 여럿인데 정답지는 없는 수학 문제를 모델에게 맡겼다고 해 보자.”

RLCD의 Paper/Abstract/Executive Summary 순서는 상세글 규칙과 정확히 맞는다. 다만 Paper 문단은 소속·분류·인쇄면 머리글까지 한꺼번에 들어가 길다. 제목, 저자, venue, 판본, PDF, 코드만 본문 첫 화면에 남기고 `cs.CL`, 소속, 머리글 확인은 “공개된 것과 확인하지 못한 것”으로 옮겨도 된다.

발행 데이터에서는 다음 필드를 맞춘다.

| 필드 | 권장값 |
| --- | --- |
| title | `RLCD: Reinforcement Learning from Contrastive Distillation for LM Alignment` |
| slug | `rlcd` 또는 충돌 시 `rlcd-contrastive-distillation-lm-alignment` |
| excerpt | 현재 문장을 1~2문장, 약 100~150자로 유지 |
| category | `paper-review` |
| tags | `rlcd`, `rlhf`, `rlaif`, `preference-data`, `context-distillation`, `ppo`, `llm-alignment` |
| thumbnail_url | `/api/blog/figures/rlcd-fig1-comparison.png` |
| content | 별도 쉽게 읽기 원고 |
| deep_content | 수정한 현재 상세 원고 |

### 2. 요약 방식

최근 상세글의 Executive Summary는 연구 질문, 방법, 핵심 결과, 핵심 한계를 4~6행 안에 압축한다. SkillOpt는 “저자 보고 기준”, “평가된 52개 셀”, “strict-best/tied-best 분해는 미보고”를 한 행에 함께 둔다. 강한 결과와 적용 범위를 동시에 보여 주는 방식이다.

RLCD의 9행 표는 정확하지만 본문을 미리 너무 많이 말한다. 아래 6행이면 충분하다.

1. 연구 질문
2. 생성 절차와 자동 라벨의 핵심
3. 7B 결과
4. 30B 결과
5. 선호 모델·기준선 조건
6. 핵심 한계: 길이 미통제와 zero-shot RLAIF

`프롬프트 설계 기준`, `정렬 대상`, `기준선`의 세 행은 방법·실험 설정 본문으로 내려도 된다. 숫자는 대표값만 남기고, 7B/30B의 방향이 달라진다는 사실을 가장 먼저 보이게 한다.

### 3. 본문 논증의 리듬

집현전 상세글의 공통 리듬은 다음과 같다.

> 문제를 먼저 정의한다 → 방법의 최소 단위를 설명한다 → 결과표를 읽는다 → 무엇이 따라오고 무엇이 따라오지 않는지 가른다 → 재현·적용 조건으로 닫는다.

짧은 예문이 이 태도를 잘 보여 준다.

- `skillopt-...`: “이 비유는 수렴 정리가 아니다.”
- `multi-token-prediction`: “실제 효과와 구분해서 읽어야 한다.”
- `rlt`: “이 아이디어만으로 모델이 더 똑똑해졌다고 말할 수는 없다.”
- `ttpo`: “이 숫자를 다른 모델이나 분야의 일반 비율로 읽을 수는 없다.”
- `rsi-roadmap`: “다섯 수준은 미래를 예언하거나 AI의 성적을 매기지 않는다.”

RLCD도 이 리듬을 대체로 지킨다. 특히 “길이 교란은 배제할 수 없되 이득 전체를 설명하지도 못한다”는 문장은 집현전식 비판의 좋은 예다. 반면 아래 표현은 근거는 충분해도 어조가 연속될 때 공격적으로 들린다.

- “라벨을 정해 버린다”
- “equal이 네 칸 중 둘을 감당한다”
- “relatively equal이 28.2점 차를 덮는다”
- “감추지는 않되 순서는 자기 쪽이 앞이다”
- “보고하지 않아도 됐을 것들이다”

권장 치환은 비판을 약화시키는 것이 아니라 판정의 단위를 분명히 하는 것이다.

| 현재 표현 | 권장 표현 |
| --- | --- |
| 라벨을 정해 버린다 | 생성에 사용한 대비 프롬프트를 기준으로 라벨을 자동 부여한다 |
| equal이 … 감당한다 | 네 칸 중 두 칸의 결론은 실질적으로 동률이라는 해석에 의존한다 |
| 28.2점 차를 덮는다 | 35.9/64.1에는 `relatively equal`이라는 캡션이 잘 맞지 않는다 |
| 감추지는 않되 순서는 자기 쪽이 앞이다 | 불리한 절대값도 보고하지만, 서술은 상대 우위를 먼저 제시한다 |
| 보고하지 않아도 됐을 것들이다 | 저자에게 불리할 수 있는 통제 결과까지 공개했다는 점은 긍정적이다 |

이렇게 바꾸면 독자는 해설자의 감정이 아니라 표와 문장의 불일치를 보게 된다.

### 4. 수식과 개념 설명

최근 글은 수식이 필요한 논문에서는 수식을 피하지 않지만, 수식 전에 기호의 역할을 설명한다. `ttpo`는 집합과 교사를 먼저 정의한 뒤 목적함수를 놓고, `multi-token-prediction`은 수식 뒤에 어떤 비교가 가능한지와 불가능한지를 바로 적는다. 쉽게 읽는 글은 수식을 거의 쓰지 않는다.

RLCD는 이론 부록을 모두 말로 풀어 정확하지만, 9절에서 독자가 확률 모형을 다시 구성해야 한다. 상세글에는 아래 정도의 최소 정식화가 있으면 좋다.

- 속성 점수: \(A(o) \sim \mathcal N(\mu(p), \sigma_G)\)
- 채점: \(\operatorname{sign}(A(o_1)+e_1-A(o_2)-e_2)\)
- 대비의 핵심: \(\mu(p^+) - \mu(p^-)\)

수식 직후에는 “이 모형은 실제 선호 데이터의 분포를 추정한 것이 아니라, 생성 분리와 채점 잡음의 관계를 보이기 위한 단순화”라고 경계를 붙인다. 쉽게 읽는 글에서는 수식을 빼고 “두 생성 분포를 먼저 벌려 채점기가 헷갈릴 쌍을 줄인다”로 설명한다.

### 5. 표와 숫자

집현전 표는 주로 다음 세 기능에만 쓴다.

- 방법 구성요소와 역할 대응
- 직접 비교 가능한 결과
- 적용 또는 재현 점검표

RLCD의 표 6개는 모두 이 기능 안에 있다. 다만 Executive Summary가 이미 결과를 자세히 싣고, 5·6절에서 다시 표로 반복하므로 요약표의 숫자를 줄여 중복을 낮춘다. 숫자 뒤에는 계속 다음 표현을 유지한다.

- “저자 보고 기준”
- “사람 평가 200예제”
- “GPT-4 이진 판정 1000예제”
- “길이를 통제한 비교는 없다”
- “30B에서 과제별로 방향이 갈린다”

“거의 사라진다”, “크다”, “압도한다”처럼 크기를 평가하는 말에는 수치를 같은 문장이나 바로 아래 표에 붙인다. 통계적 유의성이 없으면 “유의하게”를 쓰지 않는다.

### 6. 그림과 캡션

최근 글의 캡션은 보통 2~4문장으로 다음을 담는다.

1. 무엇을 보여 주는가
2. 무엇을 함께 읽거나 구분해야 하는가
3. 원논문 Figure 번호·쪽·판본
4. 그대로 인용/직접 추출/재구성 여부

RLCD Figure 1 캡션은 약 한 문단 전체를 화면 낭독에 쓰고, Figure 2도 인터페이스 문구를 거의 전부 재현한다. 이는 증거 장부에는 유용하지만 블로그 캡션으로는 길다. 다음처럼 줄인다.

> *그림 1. RLCD는 같은 입력을 대비되는 \(p^+\)·\(p^-\)로 바꾸고 각 출력의 출처로 선호 라벨을 자동 부여한다. RLAIF의 사후 LLM 채점, Context Distillation의 단일 긍정 출력 학습과 비교된다. 원논문 Figure 1, p. 2를 직접 추출했다(arXiv:2307.12950v3).*

Figure 2는 다음 정도면 충분하다.

> *그림 2. 사람 평가는 동점 선택지 없는 1~8 척도를 사용하며, 지시문은 오래 고민하지 말고 첫 반응으로 판단해도 된다고 안내한다. 길이 차이가 판정에 섞일 가능성을 검토할 때 함께 읽어야 한다. 원논문 Figure 2, p. 20을 직접 추출했다(arXiv:2307.12950v3).*

이미지 경로는 PaperWiki 상대 경로 `figures/...`와 블로그 공개 경로가 다르다. 블로그 본문에서는 `/api/blog/figures/rlcd-fig1-comparison.png`처럼 쓴다. 그림 원본을 그대로 썼다면 “원문 인용”보다 “원논문 도판 영역 직접 추출”이 현재 게시물의 일관된 표현이다. 재구성했다면 반드시 “재구성”으로 바꾼다.

### 7. 비판 강도와 근거 라벨

최근 강한 리뷰도 비판을 피하지 않는다. `evo-ontology`는 초록과 본문의 백본 수 불일치를 직접 지적하고, `ttpo`는 도식의 21%와 그래프에서 읽히는 9%를 분리하며, `rsi-roadmap`은 491편 모집단이 확인되지 않는다고 적는다. 공통점은 다음 세 가지다.

1. 먼저 논문이 실제로 보고한 사실을 적는다.
2. 직접 재계산 또는 표 대조로 확인되는 범위만 단정한다.
3. 원자료가 없으면 오류라고 확정하지 않는다.

RLCD의 10.1 `논문이 스스로 밝힌 한계`와 10.2 `해설자 관점` 분리는 이 규칙과 잘 맞는다. 그대로 유지한다. 다만 10.2의 항목이 13개라 핵심 비판이 평평해진다. 발행 본문에서는 다음 5개를 중심 비판으로 남긴다.

1. 30B 결과와 “모든 기준선보다 우수”라는 문장의 불일치
2. 길이 미통제와 평가 지시문의 결합
3. zero-shot RLAIF라는 주 기준선 조건
4. 선호 모델의 낮은 절대 사람 일치도
5. 규모별 프롬프트 강도 조정이 시험되지 않음

나머지는 “기타 원문 대조 메모”로 짧게 묶거나 삭제한다. 특히 Table 23의 59.0 대 60% 경계, Table 31의 3B/30B 오기, 부록 L/M 미참조는 정확하지만 논문의 기여 판단을 바꾸는 핵심 항목은 아니다.

비판 문장에는 필요에 따라 아래 라벨을 문장 속에 자연스럽게 넣는다.

- 논문 직접 진술: “논문은 …라고 적는다.”
- 표에서 직접 확인: “Table 3 기준으로 …”
- 설정에서의 직접 추론: “이 설정만으로는 …을 분리할 수 없다.”
- 미검증 가설: 최종 본문에서는 빼거나 “가능성”으로 제한

### 8. 결론

최근 상세글의 결론은 칭찬과 비판의 균형보다 다음 세 질문에 답한다.

1. 이 논문의 실제 기여는 무엇인가?
2. 어떤 조건에서 결론이 성립하는가?
3. 다음 실험에서 무엇을 확인해야 하는가?

RLCD 결론의 첫 문장, “선호쌍을 만드는 단계를 건드린 데 있다”는 매우 좋다. 이를 결론의 중심축으로 유지한다. 그다음은 저자의 성실성 평가보다 사용 조건을 앞세우는 편이 집현전답다.

권장 순서는 다음과 같다.

1. 생성 분포를 대비시키고 사후 채점을 제거한 기여
2. 7B에서는 강하지만 30B에서는 우위가 과제별로 갈린다는 조건
3. 길이 통제·few-shot 기준선·규모별 프롬프트 강도 조정이 필요한 이유
4. “RLCD의 핵심은 RLAIF의 대체 선언이 아니라, 선호쌍의 난이도와 라벨 잡음을 생성 단계에서 설계할 수 있다는 관찰”로 마무리

“실증도 성실한 편이다”와 “보고하지 않아도 됐을 것들이다”는 저자 태도 평가로 읽힌다. “불리한 절대값과 통제 실험도 함께 공개해 결과의 경계를 확인할 수 있다”로 바꾸면 근거 중심의 결론이 된다.

### 9. References

집현전 발행본은 `## References`로 끝나며, 본문에서 실제로 사용한 자료를 APA에 가깝게 적는다. RLCD의 32개 목록에는 본문 논증에서 직접 쓰지 않은 contrastive RL 계열과 일반 소개 자료가 섞여 있다. 최소한 다음 중심 문헌만 남기고 실제 인용 여부에 따라 추가한다.

- Bai et al. (2022b), Constitutional AI/RLAIF
- Snell et al. (2022), context distillation
- Dubois et al. (2023), AlpacaFarm

번호 목록은 쓰지 않고, 저자 표기는 `&`, 제목은 sentence case, venue/arXiv와 URL을 가능한 범위에서 채운다. DOI나 상세 서지를 확인하지 못했으면 만들지 않는다. Anthropic/OpenAI/MosaicML 소개 글은 본문에서 직접 논증에 쓰지 않으면 제거한다.

### 10. 쉽게 읽기와 상세 읽기의 분리

최근 발행물은 `content`와 `deep_content`의 역할이 분명하다.

| 구분 | 쉽게 읽기 (`content`) | 상세 읽기 (`deep_content`) |
| --- | --- | --- |
| 길이 | 대체로 4,700~7,500자 | 대체로 11,000~35,600자 |
| 도입 | 사고실험·비유·핵심 질문 | Paper/Abstract/Executive Summary |
| 수식 | 거의 없음 | 필요한 수식과 기호 설명 |
| 표 | 0~1개가 보통 | 결과·구성·점검표 |
| 비판 | 가장 중요한 경계 2~4개 | 표·부록·재현 조건까지 상세 대조 |
| 연결 | 끝에서 상세 읽기 링크 | 독립적으로 완결 |

RLCD의 쉽게 읽기는 다음 6절이면 충분하다.

1. `# 같은 질문에서 두 답을 고르지 않고, 반대 프롬프트에서 답을 하나씩 뽑는다 — 쉽게 읽는 RLCD`
2. 왜 같은 프롬프트에서 뽑은 두 답은 구분하기 어려운가
3. RLCD가 선호쌍을 만드는 방법
4. 7B에서는 무엇이 좋아졌나
5. 30B에서는 왜 결론이 달라지나
6. 길이와 기준선 때문에 주의해서 읽을 점

도입 예시는 다음 정도가 집현전 톤에 맞는다.

> 같은 질문에 비슷한 답 두 개가 나오면 어느 쪽이 더 나은지 가르기 어렵다. RLCD는 비교자를 더 똑똑하게 만드는 대신, 처음부터 차이가 더 잘 드러나는 답 두 개를 만든다. 하나에는 원하는 성질을, 다른 하나에는 반대 성질을 유도하는 짧은 문구를 붙인다. 어느 문구에서 나온 답인지 알기 때문에 별도 채점 모델 없이 선호 라벨을 만들 수 있다.

쉽게 읽기의 마지막에는 “7B에서는 큰 차이가 났지만, 30B에서는 사람 평가가 동률에 가까웠고 GPT-4 평가는 두 과제에서 RLAIF를 더 선호했다. 따라서 이 글은 RLCD를 보편적 대체재보다 작은 모델과 잡음 많은 채점에서 유리한 데이터 생성 전략으로 읽는다”라고 범위를 닫는다.

## RLCD 초안의 강점

다음 요소는 수정 과정에서 보존해야 한다.

- 7B와 30B를 한 헤드라인으로 합치지 않는다.
- 사람 평가와 GPT-4 평가를 분리한다.
- 길이 교란을 제기하되 전체 이득의 원인이라고 단정하지 않는다.
- 논문이 스스로 인정한 한계와 해설자의 대조 결과를 분리한다.
- “공개된 것과 확인하지 못한 것”에서 실제 검증 범위를 밝힌다.
- 적용 점검표를 모델 규모, 프롬프트 강도, 길이 통제, 기준선, 무해성-도움성 균형으로 구체화한다.
- 논문에 불리한 수치뿐 아니라 통제 실험과 저자의 한정 문구도 함께 적는다.
- 각 주요 수치에 표·절·부록 링크를 붙인다.
